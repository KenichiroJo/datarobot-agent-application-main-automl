## ペルソナ

### ペルソナ: 田中（審査担当者）
- **役割**: 融資審査担当者
- **目標**: 個別顧客の審査を効率的に行い、適切な通知文書を素早く作成したい
- **課題**: 審査結果の文書作成に時間がかかる。モデル予測の根拠を顧客に説明しにくい
- **技術レベル**: 初心者（AIモデルの詳細は理解していない）
- **使用頻度**: 日次

### ペルソナ: 佐藤（リスクマネージャー）
- **役割**: リスク管理部門マネージャー
- **目標**: モデル全体の予測性能を把握し、リスク要因のトレンドを監視したい
- **課題**: DataRobotのUI操作に慣れておらず、チームへの報告資料作成が手間
- **技術レベル**: 中級者
- **使用頻度**: 週次

### ペルソナ: 山田（データサイエンティスト）
- **役割**: モデル開発・運用担当
- **目標**: モデルの振る舞いを深堀りし、改善ポイントを特定したい
- **課題**: 複数のインサイトを横断的に分析するのが煩雑
- **技術レベル**: 上級者
- **使用頻度**: 日次

## EP-001: 予測コンテンツ生成

### US-001: 顧客を選択して予測結果を確認する

**ユーザーストーリー**
> 審査担当者として、データセットから顧客を検索・選択して貸倒リスクの予測結果を一目で確認したい。なぜなら迅速に審査判断を下す必要があるから。

**受入基準**
```gherkin
Scenario: 顧客の検索と選択
  Given Contentダッシュボードが表示されている
  When 顧客セレクターに名前やIDの一部を入力する
  Then フィルタされた候補がドロップダウンに表示される
  And 候補を選択すると予測カードが表示される

Scenario: 予測結果の表示
  Given 顧客が選択されている
  When 予測APIの応答が返ってくる
  Then 円形ゲージに予測確率が表示される
  And リスクレベル（高/中/低）がバッジで色分け表示される
  And 上位10件の特徴量説明が横棒グラフで表示される
```

**優先度**: Must
**見積り**: M
**依存関係**: なし

### US-002: 予測理由を特徴量説明で理解する

**ユーザーストーリー**
> 審査担当者として、なぜこの予測結果になったかを特徴量の影響度で理解したい。なぜなら顧客に説明責任があるから。

**受入基準**
```gherkin
Scenario: 特徴量説明の表示
  Given 予測結果が表示されている
  When 特徴量説明パネルを確認する
  Then 各特徴量の名前、値、影響度（正/負）が表示される
  And 正の影響は赤系、負の影響は青系で色分けされている

Scenario: テキスト特徴量のngram表示
  Given テキスト特徴量が予測に寄与している
  When ngramハイライトセクションを確認する
  Then 重要なテキスト箇所が色付きでハイライトされている
```

**優先度**: Must
**見積り**: M
**依存関係**: US-001

### US-003: 承認/却下レターを自動生成する

**ユーザーストーリー**
> 審査担当者として、予測結果に基づく承認または却下のレターを自動生成したい。なぜなら文書作成の時間を大幅に削減したいから。

**受入基準**
```gherkin
Scenario: 承認レターの生成
  Given 予測結果でリスクが低いと判定された顧客が選択されている
  When 「承認レター」タブで「生成」ボタンを押す
  Then エージェントが予測結果と特徴量説明を元に承認レターを生成する
  And レターがタブ内に表示される

Scenario: 却下レターの生成
  Given 予測結果でリスクが高いと判定された顧客が選択されている
  When 「却下レター」タブで「生成」ボタンを押す
  Then 却下理由を含むレターが生成される
```

**優先度**: Must
**見積り**: L
**依存関係**: US-001

### US-004: 顧客向け説明文書を生成する

**ユーザーストーリー**
> 審査担当者として、顧客に送付する審査結果の説明文書を平易な言葉で自動生成したい。なぜなら専門用語を使わずに顧客が理解できる文書を作る必要があるから。

**受入基準**
```gherkin
Scenario: 顧客向け説明の生成
  Given 予測結果が表示されている
  When 「顧客向け説明」タブで「生成」ボタンを押す
  Then 専門用語を使わない平易な説明文書が生成される
  And 主要な判断根拠が顧客にわかる形で含まれている
```

**優先度**: Must
**見積り**: M
**依存関係**: US-001

## EP-002: モデルインサイト深堀り

### US-007: モデルの精度サマリーを確認する

**ユーザーストーリー**
> リスクマネージャーとして、モデルの主要な精度指標（AUC, F1, LogLoss, Accuracy）を一目で確認したい。なぜなら定期的なモデル性能レビューに使いたいから。

**受入基準**
```gherkin
Scenario: 精度サマリー表示
  Given Insightsダッシュボードにアクセスする
  When ページが読み込まれる
  Then 画面上部にKPIカード群（AUC, F1, LogLoss, Accuracy）が表示される
  And 各値は小数点以下2-4桁で表示される
```

**優先度**: Must
**見積り**: M
**依存関係**: なし

---

### US-008: 特徴量の重要度を確認する

**ユーザーストーリー**
> データサイエンティストとして、モデル全体でどの特徴量が最も予測に影響しているか確認したい。なぜならモデル改善の優先順位を決めたいから。

**受入基準**
```gherkin
Scenario: Feature Impactチャート表示
  Given Insightsダッシュボードが表示されている
  When Feature Impactセクションを確認する
  Then 特徴量が重要度順に横棒グラフで表示される
  And 各棒にホバーすると具体的な数値がツールチップで表示される
```

**優先度**: Must
**見積り**: M
**依存関係**: US-007

## EP-003: 対話型分析

### US-015: チャットでモデルインサイトを深堀りする

**ユーザーストーリー**
> リスクマネージャーとして、モデルのインサイトについてチャットで質問して自然言語で解説を得たい。なぜなら技術的なグラフだけでは理解が難しい場合があるから。

**受入基準**
```gherkin
Scenario: インサイトの自然言語解説
  Given Insightsダッシュボードのサイドチャットが開いている
  When 「なぜ年収が最も重要な特徴量なのですか？」と入力する
  Then エージェントがFeature Impactデータを参照して解説を返答する

Scenario: チャートコンテキストの自動付与
  Given Feature Impactチャートが表示されている
  When サイドチャットで質問する
  Then エージェントは現在表示中のチャートのコンテキストを理解して応答する
```

**優先度**: Must
**見積り**: L
**依存関係**: US-007, US-008

---

### US-016: チャットで個別顧客の深堀り分析を行う

**ユーザーストーリー**
> 審査担当者として、特定の顧客についてチャットでより詳しい分析を依頼したい。なぜなら定型的な説明以上の洞察が必要な場合があるから。

**受入基準**
```gherkin
Scenario: 顧客の詳細分析
  Given Contentダッシュボードで顧客が選択されている
  When サイドチャットで「この顧客のリスク要因をもっと詳しく教えて」と入力する
  Then エージェントが予測説明を深堀りし、追加のコンテキストを含む詳細分析を返答する
```

**優先度**: Must
**見積り**: L
**依存関係**: US-001, US-002

### US-017: 画面遷移でモードを切り替える

**ユーザーストーリー**
> 全ユーザーとして、左側のナビゲーションからContent/Insights/Chatモードをスムーズに切り替えたい。なぜなら分析の文脈を保ちながら別の視点に移りたいから。

**受入基準**
```gherkin
Scenario: モード切り替え
  Given いずれかの画面が表示されている
  When 左ナビゲーションの別モードアイコンをクリックする
  Then 対応する画面に切り替わる
  And 500ms以内に遷移が完了する
```

**優先度**: Must
**見積り**: S
**依存関係**: なし
